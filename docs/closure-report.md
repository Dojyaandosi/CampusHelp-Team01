## 3. Major issues

1. Wireframes (T05) took one hour more than planned, which delayed the risk register (T06) and milestone M2 by one day.
2. Both prototypes depended on T05, so the same delay moved M3 by one day.
3. Change request CR-01 arrived on Day 6 and had to be evaluated without breaking the baseline; it was deferred.

## 4. Lessons learned

- Dependencies matter: a one-hour overrun on a task with two successors delays two milestones.
- Estimates for design tasks need contingency; a 10 % buffer would have absorbed the T05 overrun.
- Formal change control protected scope and budget; the out-of-scope list in the charter made the decision fast.
- GitHub Issues, Milestones and the Projects board (Board / Table / Roadmap) gave a single view of progress, and the checkpoint formula (actual % - planned %) exposed delay even when much work was done.
- Quality checks should start as soon as the first prototype exists, not only at the end.
